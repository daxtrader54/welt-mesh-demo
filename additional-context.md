## Additional Product Context

This application should be approached as the kind of working prototype a Solutions Architect could use to help a merchant understand how Mesh fits into their own product.

The Mesh integration itself should feel straightforward. The differentiation should come from the quality of the customer experience, how clearly the integration is communicated, and how well failure states and operational details have been considered.

Prioritise:

1. A believable merchant experience
2. Fast, obvious understanding of the value of Mesh
3. Strong happy-path UX
4. Thoughtful failure handling
5. Useful integration telemetry behind an optional technical view, think events log
6. Clear documentation
7. Reliability during a live demonstration

Do not add complexity simply to demonstrate engineering effort.

A polished, focused implementation with clear reasoning is better than integrating every available feature.
